## Offline Genesis Wi-Fi build

Export the committed recipes and their SHA256-pinned source archives on the
development host with `scripts/export-genesis-wifi.sh /path/to/bootstrap.tar.gz`.
In a snapshot-mode Genesis VM, extract the bundle under a temporary directory
with mode 0755 and run `python3 genesis-wifi/build.py`. The driver requires
x86_64 glibc 2.44 and uses an unprivileged build account when invoked by root.
It builds libnl before wpa-supplicant, then installs and verifies both packages
in a temporary target root. The build does not require EeePC network access.

Verified in development: 28 automated tests passed, the exporter produced a
bundle whose seven manifest entries all verified, and the native driver rejected
the development host's incompatible glibc. Native Genesis builds and EeePC Wi-Fi
association remain pending. NetworkManager and nmtui remain pending.

### Native graphics boot on the physical EeePC

Selected the serial-console GRUB entry, which booted without nomodeset.
Baihu reconnected over SSH. The running system exposed /dev/dri/card0 and
/dev/dri/renderD128, while the built-in display remained black. DRM device
enumeration passed. Panel output and GUI operation remain unverified. The next
check is the DRM connector status, available modes, and kernel display logs.

The Pineview i915 driver initialized. LVDS-1 was enabled with unknown status
and an empty mode list; VGA-1 was disconnected. The acpi_video0 backlight
reported brightness 15/15, actual brightness 15, and bl_power 0. No fb device
was listed in sysfs. These observations do not identify the cause of the black
panel. Next capture the BIOS revision, framebuffer console configuration, and
any VBT or panel-related kernel messages.

DMI identified the physical unit as ASUS 1005PE, BIOS 1003 (2010-03-18).
The filtered log showed two ACPI SystemIO/SMRG conflicts and no explicit
VBT, LVDS, EDID, or fbcon diagnostic. The SMRG warnings do not establish
a connection to the black panel. The running kernel's fbdev and console
configuration has not yet been captured.

The Baihu EeePC kernel bundle contains its resolved configuration as ./config.
It reports CONFIG_VT_CONSOLE=y and CONFIG_DRM_I915=y, with DRM framebuffer
emulation and CONFIG_FB disabled. The running system did not expose
/proc/config.gz. Added explicit i915, DRM framebuffer emulation and framebuffer
console settings to the EeePC profile. Kconfig resolution, kernel compilation
and physical panel output remain to be verified.
